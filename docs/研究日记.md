# 研究日记

> 课题：校园宠物乐园——基于 Web 的班级积分管理与宠物养成系统
> 时间：2026 年 8 月上旬至中旬
> 说明：本日记按课题四个阶段记录，共 5 篇，内容与《研究性学习课题材料》中的研究过程保持一致。

---

## 第 1 篇（8 月 8 日，课题立项）

今天确定了研究性学习的课题。老师给了几个方向，我们组一开始讨论了很久没定下来。后来看了几个现成的班级积分系统，觉得"积分 + 宠物养成"这个方向比较有意思，学校一体机也能用上，就定了这个题目。

组内分工的时候说实话有点尴尬：大家都说自己不太会写程序，最后商量下来，由我主要负责代码开发，其他同学负责收集资料、测试和后期整理材料。分工就暂时这么定了，我心里清楚后面大部分活可能都得自己干，但既然定了课题，就先做起来再说。

今天的收获是：确定了课题名称《校园宠物乐园——基于 Web 的班级积分管理与宠物养成系统的设计与实现》，并给研究计划排了个大致时间表。

## 第 2 篇（8 月 11 日，需求分析）

这两天主要在"摸底"。我们把 GitHub 上能搜到的班级积分、宠物养成类开源项目都翻了一遍，重点看了两个：一个是纯前端的 classroom-pet-system，功能很全（孵化、四维状态、道具商店、排行榜都有），但数据存在浏览器 localStorage 里，换个设备就没了；另一个是 class-pet-garden，用的是 Vue 3 + Node.js + SQLite，架构正好是我们想学的，但它没做商店和用户系统，还明确写着不允许直接抄代码。

看完之后需求就清晰了：我们要做的是一个**能在一体机上长期运行、数据不丢、界面好看**的系统。功能清单定为三块——积分管理、宠物养成与商店、排行榜与大屏展示，另外还要加上数据备份和同步，不然学校老师不敢用。技术栈也定了：前端 Vue 3 + TypeScript + Tailwind CSS，后端 Node.js + Express + SQLite。这一天把原型布局在纸上画了画，算是把阶段一收尾了。

## 第 3 篇（8 月 13 日，开发进行中）

开发开始后才发现，写代码比想的费时间。这两天先搭了前后端框架，然后把最核心的积分模块写完了：加分、扣分、批量操作、理由必填、流水记录，加减分放在数据库事务里做，避免并发出错。接着开始写宠物模块，12 种宠物、7 个成长阶段，还有健康/饱食/心情/清洁四项属性和状态规则——宠物"生病""睡觉""开心"这些状态其实是一张规则表算出来的，不是写死的，这个设计让我挺有成就感。

中间也踩了不少坑：比如 Node 的 SQLite 模块版本问题、Vue 组件传参报错。组员这两天帮我整理了功能清单和要截图的内容，我专心写代码，配合还算顺利。

## 第 4 篇（8 月 15 日，功能打通 + 开始测试）

今天把所有模块串起来了：学生端能领养宠物、逛商店、用道具；教师端能加减分、看排行榜；大屏模式能自动轮播排行榜和宠物墙。第一次完整跑通的时候还是很兴奋的，毕竟整个系统从无到有。

下午开始测试，把之前写好的单元测试（数据层、同步引擎、冲突处理这些）和端到端冒烟测试脚本跑了一遍，发现两个问题：一个是批量加减分在连续快速点击时偶发重复提交，另一个是大屏在触屏上按钮太小不好点。晚上改了一部分，剩下的明天继续。

## 第 5 篇（8 月 16 日，收尾）

最后一天主要干三件事：修完剩下的 bug、在一体机上实际部署试运行、整理材料。一体机运行效果不错，大屏模式全屏展示排行榜挺有模有样的，触屏操作也比之前顺了。组员们帮忙录了演示视频、截了各个界面的图，还找班里几个同学试用了一下，反馈是"挺好玩""比贴纸积分有意思"，也有同学建议多加点宠物种类。

下午把运行截图、核心代码截图、测试结果和这份日记整理归档，开始写研究报告。整个课题做完最大的感受是：**一个人撑起一个项目真的很累，但把一个想法做成能跑的东西，成就感也是真的**。下次再有小组合作，一定先把分工说清楚、定期对进度，不能全靠一个人扛。
