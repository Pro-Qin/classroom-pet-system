# 调研记录

> 课题：校园宠物乐园——基于 Web 的班级积分管理与宠物养成系统
> 调研时间：2026 年 8 月上旬
> 调研人员：（课题组全体成员）
> 详细资料：见《调研报告-校园宠物系统》（同目录）

---

## 一、调研目的

确定课题的技术路线：先了解 GitHub 上已有的班级积分 / 宠物养成类开源项目，弄清它们"做了什么、缺什么"，再决定我们自己的系统怎么做，避免从零设计、重复造轮子。

## 二、调研方法

1. 在 GitHub 上用"班级积分""宠物养成""classroom pet"等关键词搜索开源项目；
2. 阅读各项目的 README、功能说明和部分源码，记录技术栈与功能清单；
3. 对重点项目尝试本地运行或查看在线演示，确认实际效果；
4. 制作对比表，分析每个项目的优缺点，得出选型结论。

## 三、调研对象与对比

| 项目 | 技术栈 | 优点 | 不足 |
|------|--------|------|------|
| classroom-pet-system（开源） | Vue 3 + CSS，纯前端 | 玩法完整：宠物孵化、四维状态、道具商店、成长升级、任务、积分、排行榜、教师端/管理端 | 数据存浏览器 localStorage，换设备就丢，无法多人共享；单机运行 |
| class-pet-garden（开源，无 License） | Vue 3 + TypeScript + Tailwind + Node.js + Express + SQLite | 前后端架构完整，SQLite 单文件存储，备份方便；有 24 种宠物、83 条评价规则 | 未做商店和用户系统；作者未开放代码使用权，只能参考架构，不能直接抄 |
| 各类纯积分系统（Siqams、cqes4cs、班级积分奖惩抽奖系统、AxleScore 等） | Java / PHP / Python 等 | 积分考核功能成熟，可参考加分规则与流水设计 | 没有宠物玩法，界面多为传统风格，不适合一体机展示 |

## 四、调研结论

1. **现成的"积分 + 宠物"一体化方案很少**，仅有的两个开源项目各有明显短板：一个不能多设备共享数据，一个功能不完整且不能复用代码。
2. **确定参考路线**：架构和数据库设计参考 class-pet-garden（Vue 3 + Node.js + SQLite），玩法设计参考 classroom-pet-system（宠物状态、商店、排行榜），但代码全部自主开发。
3. **需要自己补上的功能**：独立的学生/教师/管理三套用户界面、道具商店与背包、大屏轮播模式、数据备份与云端同步、登录安全（密码哈希、限流）。
4. **部署方式**：采用 SQLite 单文件数据库 + 本地构建产物，做到学校一体机离线可用，双击启动脚本即可运行，避免依赖外网。

## 五、调研对课题的指导意义

本次调研让课题避免了两个弯路：一是没有盲目从零设计功能，而是先弄清已有方案的长短处；二是明确了"架构参考开源、代码自主实现"的原则，保证了系统的原创性，也确定了研究内容（三个核心模块 + 数据同步安全）和研究过程（先跑通、再完善）的具体安排。
